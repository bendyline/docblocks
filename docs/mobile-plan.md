# DocBlocks mobile app implementation plan

Build an offline document editor for iPhone, iPad, and Android using Capacitor and the existing `DocBlocksShell`. The mobile package owns platform integration; `packages/core`, `packages/react`, and Squisq continue to own document behavior and the editor. The first usable device milestone is a development build on the connected iPhone and an Android test device that can edit, save, and reopen Markdown offline.

The implementation now lives in `packages/mobile`, following the sibling Gezel infrastructure. The original design below is retained as the qualification contract. This record was updated on October 4, 2026. The five implementation phases are present; phase 5 release qualification remains incomplete.

**Use a thin mobile package.** Proposed files are `packages/mobile/src/main.tsx`, `host.ts`, `native.ts`, `browser-host.ts`, `App.tsx`, `vite.config.ts`, and `capacitor.config.ts`, plus `native/ios`, `native/android`, `ios`, `android`, and `scripts`. Use a provisional application ID of `com.bendyline.docblocks.mobile`, subject to the signing team's existing identifiers. Native project configuration and source are tracked; copied bundles, caches, and build products are ignored.

Bootstrap reads and validates native app metadata, opens the storage adapter, installs `globalThis.docBlocksHost`, and only then imports the React entry point. A storage initialization failure presents a retryable error without switching to an empty workspace. Browser development uses an explicitly separate IndexedDB workspace. It exposes only the capabilities available in that preview.

The packaged app contains its JavaScript, fonts, Squisq assets, Monaco workers, Harper engine and license, and IronCalc WASM. Reuse the existing asset staging helpers. Keep the installed WebView origin stable across updates, and qualify workers, WASM, asset URLs, and the content security policy on both platforms. App releases carry the web bundle; the native app does not need the site's PWA update flow. Capacitor's standard workflow builds web assets before copying them into native projects with `cap sync`. [Capacitor workflow](https://capacitorjs.com/docs/basics/workflow)

**Adapt the existing host contract.** The [host environment](../packages/core/src/host/capabilities.ts) already recognizes Capacitor, iOS, and Android. Preserve capability derivation from actual bridge methods. Add optional method declarations where a desktop-oriented namespace currently requires unsupported members, including folder picking, file-manager actions, remembered export targets, clipboard paths, and window-close commands. Mobile can expose clipboard text and external navigation without exposing the other desktop methods.

Extract the renderer transport logic from [ElectronFileSystemProviderV2](../packages/core/src/filesystem/electron-provider-v2.ts) into a host-neutral client, retaining the Electron API as a compatibility wrapper. It currently fixes the capability values to Electron's and rejects different values returned by `open`; the generic client must validate and use the backend's actual capabilities and budgets. Keep literal dynamic imports and the v1 facade only for existing shell compatibility.

Introduce a host-owned workspace descriptor kind, such as `host-native`, with a persisted-descriptor migration for `electron-native`. Native workspace IDs remain authoritative; native paths, iOS bookmarks, and Android content URIs stay private to the host. Startup reconciliation, hash navigation, recent documents, and pinned documents must use those IDs. All shared wire additions and exact parsers belong in `packages/core`.

**Implement storage as a native correctness boundary.** A DocBlocks Capacitor plugin resolves registered workspace IDs and reparses canonical workspace paths on every call. Its native backend owns conditional writes, creation modes, rename without replacement, containment, typed errors, snapshots, and disposal. Serialize cooperating mutations and publish file replacements from operation-owned temporary files; report the achieved atomicity and durability honestly. Do not implement compare-and-write as two separate JavaScript plugin calls.

Capacitor messages need a JSON-safe byte encoding. Use bounded Base64 chunks, smaller mobile transfer budgets than the desktop's current 1 GiB file allowance, native transfer IDs, and cleanup on cancellation, timeout, or WebView loss. Establish limits from device measurements during the first storage milestone. Native responses enter TypeScript as `unknown` and pass exact shape validation. Pass the repository's filesystem v2 conformance suite against the actual native backend through device or simulator runners, alongside native fault-injection tests.

Advertise watch support only when native subscriptions implement the ready barrier, ordered events, overflow/error channels, and awaitable disposal. Providers without that guarantee report `watch: false` and explicitly observe current document versions on resume. `.dbk` conflicts preserve and resolve the complete Markdown and media tree together, using the existing session conflict rules.

Begin with an app-owned local workspace for the device pilot. Before general release, support a durable work location using iOS Files with security-scoped bookmarks and Android's Storage Access Framework with persisted grants. An iCloud container can become the iOS default after entitlement and offline/conflict qualification. Android's framework grants access to the chosen document or tree through content URIs and allows providers to expose different supported operations. [Android document storage](https://developer.android.com/training/data-storage/shared/documents-files)

Cloud and picked-folder providers must declare their own weaker capabilities where necessary. Handle unavailable files, expired grants, provider replacement, external edits, and download-on-read explicitly. An inaccessible selected root must remain visible as inaccessible. Use the app-local fallback only as an explicit storage choice. Make the pilot workspace's location and export/backup route clear because app-container documents are removed with an uninstall. Portable document history stays with the document; recovery journals and derived caches stay on the device.

**Preserve document and suspension semantics.** Every edit, transition, save, rename, and delete remains under `DocumentSession`, including editor generation scoping. Keep its bounded recovery journal and conditional-baseline recovery. Connect native foreground/background events to a deadline-aware `app-background` path; Capacitor provides foreground state events. [Capacitor App API](https://capacitorjs.com/docs/apis/app)

The current shell ignores the close request's reason and deadline, and `prepareClose()` freezes editing until `cancelClose()`. Add an explicit suspension/resumption path: flush within the available budget, retain unacknowledged recovery state, and unfreeze and revalidate the current document on resume. Correlate requests so a late background result cannot freeze a resumed editor. A background save failure stays visible on return. The OS cannot be kept alive by a confirmation dialog, and background-only saving cannot guarantee persistence. Qualify continuous saves and journal recovery under actual process termination before claiming crash recovery.

**Integrate mobile file flows and input.** Import Markdown, media, and `.dbk` through native pickers into a selected workspace. Incoming Open With requests use the existing bounded startup queue and navigation generation rules. The first release imports an editable copy; editing a provider's original file requires a later exact-resource grant implementation. Use the existing conversion registry and export pipeline, then a native Save to Files/Documents action or share sheet. Picker cancellation and sharing must not be reported as a durable save.

Retain the measured `data-db-*` layout system, mounted panes, inert hidden drawers, safe-area tokens, and touch target sizing. Feed native keyboard/inset observations into the shared shell's viewport handling without applying the same inset twice. Android Back dismisses the foremost dialog or drawer before changing navigation. Test caret visibility, selection, long press, composition, undo, rotation, hardware keyboards, tablet split view, VoiceOver, and TalkBack. Editor-internal fixes go upstream to Squisq.

Authored HTML, outside-in previews, popups, redirects, and external URLs must not inherit the app's Capacitor bridge. Mirror Gezel's isolated preview boundary and apply DocBlocks' canonical external HTTP URL policy. Test this on native WebViews, including navigation into a local preview asset.

The implementation needs to settle the application identifier, iOS signing team, minimum supported OS/WebView versions, and chosen work-folder policy before release configuration. Capacitor itself currently documents iOS 15+ with Xcode 26+ and Android API 24+; DocBlocks' editor dependencies and the optional Gezel SDK can require a newer baseline. Confirm support through hardware testing rather than inheriting the framework minimum automatically. [Capacitor iOS support](https://capacitorjs.com/docs/ios), [Capacitor Android support](https://capacitorjs.com/docs/android)

The greatest implementation uncertainty is conditional-write and crash behavior across cloud document providers. Resolve that with the storage milestone before broadening storage guarantees. After milestone 3, the development app should be useful on the attached iPhone; milestone 5 establishes distribution readiness.
