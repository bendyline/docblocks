Quick start

Create, protect, and publish a document.

The web and desktop apps share these first steps. In a fresh default workspace, open aboutDocBlocks.md for the built-in tutorial. In VS Code, create or open a Markdown file in the Explorer, then follow the same writing workflow.

1. Create or open

Choose New file in the file pane, or New document on the welcome screen. Name it my-first-document.md. Add a heading and a few sentences in Write, then switch to Source to see the same document as Markdown.

Open the web editor

2. Keep a backup

Edits save automatically in web and desktop workspaces; check any save or conflict message. Browser storage belongs to this browser profile. Follow the Backup browser docs frequently reminder and use Download all workspaces in the app menu. For native folders, use your usual file backup tools.

3. Export or share

Preview your document as a Document, Page, Slideshow, or Video, then open Export and share. Choose a format and save the result. A share link embeds a snapshot of the document in the URL; anyone with the link can read that copy, and later edits do not update it.

Keep your work portable

Move files, keep writing.

Installing another DocBlocks app does not move your existing workspaces. Choose a shared folder or make an explicit copy to continue elsewhere.

From the browser

Export Markdown with its media, or a DBK bundle that keeps documents and media together, then open it in another DocBlocks app. Keep a separate backup before clearing browser data. Installing the web app continues to use its browser profile.

Between Desktop and VS Code

Open the same folder in either app. Your Markdown and relative media links travel together. If two apps edit a document, resolve any external-change conflict before continuing. File sync, when wanted, comes from your own folder or backup service.

In a mobile preview

Use a picked folder or export and share files through the system controls. On this device storage is private to the app and is removed on uninstall. Opening a Markdown file from another app imports a copy; it does not automatically update the original.

For automated workflows, see the CLI reference and supported import and export formats.

Troubleshooting

Recover without guessing.

DocBlocks keeps failures visible instead of silently treating storage, permissions, or conversion errors as success. Start with the message on screen, then use the matching recovery path below.

A site page opens the editor

Apply the visible DocBlocks update and reload once. The corrected service worker keeps the editor at the site root while product, documentation, privacy, and terms pages use their own routes.

A document will not save

Keep the tab open. Check the storage or conflict banner, free browser space when requested, and choose a conflict branch explicitly. Download all workspaces before clearing site data.

An export fails

The export dialog remains open with the failure detail. Check unreadable images, destination permission, and available storage, then retry. A failed export never reports success or replaces an existing destination silently.

Include the version when asking for help.

Open About DocBlocks to find the version and delivery surface. Include that value, your browser or operating system, and the smallest reproducible document when reporting a problem.
