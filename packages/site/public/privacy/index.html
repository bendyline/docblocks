Privacy · Updated October 20, 2026

Local-first means your documents stay under your control.

DocBlocks has no accounts and no DocBlocks server, and the documents you edit are not sent to Bendyline. This page lists every way DocBlocks uses the network, so you can see when something leaves your device, where it goes, and why.

At a glance

  • No accounts, advertising, analytics, or crash reporting in any DocBlocks app.
  • Your documents stay on your device, or in the folders and repositories you choose.
  • AI, dictation, and read aloud run on your device. They are off until you turn them on, and models download only when you choose one.
  • A few features contact other services: desktop update checks, downloads you request, videos embedded in a document, share links, and services you connect. Each is described below.

Where your documents are kept

Web editor. Workspaces are stored in your browser’s storage on this device. If you open a local folder through your browser’s File System Access interface, DocBlocks can use only the folders you grant, and the browser may ask you to renew that permission. Browser storage can be cleared by you, by browser settings, or by the browser under storage pressure. DocBlocks offers backups and a persistent-storage request, but you remain responsible for keeping copies of important work.

Desktop app. Documents stay in the folders you open. The app keeps its settings, including the list of folders you opened, in its application data folder.

VS Code extension. It edits the files VS Code opens. Words you add to the proofing dictionary and suggestions you dismiss are kept in VS Code’s extension storage and are not synced by Settings Sync.

Mobile preview apps. Documents are kept in the app’s storage or in folders you choose. Your phone’s backup settings decide whether that storage is included in an iCloud or Google backup.

CLI and MCP server. Commands you run read and write the files you point them at. The MCP server starts with no access to your files: it can use only the folders granted with --allow-read and --allow-write, and by default keeps temporary results in your system’s temporary folder for up to 30 minutes. In the VS Code extension’s setup panel, Register DocBlocks MCP grants it read and write access to the open workspace folder.

Every app also keeps device-local data: preferences, recently opened files, a recovery copy of unsaved edits, your spelling dictionary and dismissed suggestions, and, where enabled, revision history. None of it is sent anywhere.

AI assistance

AI features are available in the desktop app and the mobile preview apps, and are off until you turn them on in Settings. Built-in AI runs models on your device, with bundled engines or, where available, Apple’s on-device Foundation Models. Your requests and the document text they include are processed on your device.

Downloads. AI models, the optional relevance model, and reference catalogs are downloaded from Hugging Face only when you choose to add them. Hugging Face receives your IP address and the files requested, under the Hugging Face privacy policy. If a Hugging Face access token is set in your environment (HF_TOKEN), it is sent with those downloads. Passages from reference catalogs you enable are found on your device and added to your AI requests there.

Connecting the Gezel app (desktop). When you open AI settings, DocBlocks checks whether the Gezel app is running on this computer. If you choose Connect Gezel app, DocBlocks sends your AI requests, including the document text they contain, to that app over a connection that stays on your computer. If you have set up Gezel to use a model hosted elsewhere, Gezel sends those requests to that provider, under Gezel’s settings and that provider’s terms. DocBlocks keeps the connection token in a file in its application data folder that only your user account can read. This option is not available in the Mac App Store version.

Reporting AI output. Report output opens a pre-filled, public GitHub issue with the reason, model, app version, and browser details. The AI’s response, which can contain text from your document, is added only if you choose Include the AI response in the report.

Models, catalogs, and engine logs are stored on your device: on desktop, in a DocBlocks folder inside ~/.gezel, or inside the app’s container in the Mac App Store version.

Dictation and read aloud (desktop)

Dictation and read aloud run on your computer; your voice and your documents never leave it. DocBlocks uses the microphone only while you dictate or record. Speech models and voices are downloaded from Hugging Face only when you choose to download them.

Spelling and grammar

DocBlocks proofing runs entirely on your device in every app. The desktop app also shows your system’s spelling suggestions when you right-click a word; on Windows and Linux, the app’s Chromium engine may download a spelling dictionary from Google for this.

Desktop updates

The desktop app from docblocks.com or GitHub checks GitHub for a new release each time it starts and when you choose Check for Updates. A new version downloads in the background and installs when you choose to restart. These requests send GitHub your IP address and a random identifier that the updater creates once and stores in the app’s data folder; it is not linked to your name or your documents. Versions installed from an app store are updated by that store, and the final Intel Mac version does not check for updates.

Content in documents that loads from other sites

A video in a document from YouTube, Vimeo, Loom, Dailymotion, or Wistia loads that provider’s player as soon as the document is shown, including in a document someone shares with you. The provider receives your IP address, browser details, and the video being shown, may learn that DocBlocks is showing it, and may set cookies, under its own privacy policy. YouTube videos load from YouTube’s privacy-enhanced youtube-nocookie.com address.

The web editor, desktop app, and VS Code extension do not load images or other files from other websites. The mobile preview apps do: remote images in a document, map tiles from OpenStreetMap, OpenTopoMap, Esri, and Stadia Maps, and video thumbnails load directly from those sites. MCP document previews can also load images a document references from other websites.

Share links

Share link with content embedded puts a copy of the document’s text in the link itself, after the #. Browsers do not send that part of an address to the website, so docblocks.com never receives it. Images are left out, and the QR code is made on your device. Anyone with the link can read the shared copy, and the text goes wherever the link goes, such as chat and email services or browser history, so do not share secrets this way.

Git (desktop)

When you push, pull, fetch, or clone, the desktop app runs Git with your credentials and exchanges repository contents with the remotes you configured, such as GitHub.

The website and the offline web app

DocBlocks.com is delivered through GitHub Pages. GitHub states that a visitor’s IP address is logged and stored for security purposes when a GitHub Pages site is visited. That hosting activity is governed by the GitHub Privacy Statement. DocBlocks sets no cookies and includes no advertising or analytics scripts.

On your first visit, the web editor saves its application files (about 80 MB) in your browser so it can work offline, and checks for a new version every hour while it is open. The Desktop download page asks GitHub’s API for the latest release, which sends GitHub your IP address, and remembers the answer in your browser for an hour.

VS Code extension and CLI

The extension makes no network requests of its own and does not use VS Code telemetry; links you click open in your browser. In its setup panel, Install DocBlocks CLI runs npm in a terminal, which downloads the CLI from the npm registry. The CLI makes no network requests of its own, and docblocks serve listens only on your computer unless you pass --allow-network.

Links and issue reports

Links to GitHub, npm, Hugging Face, Bendyline, or other external services are governed by those services’ policies. If you choose the DocBlocks issue-report link, your browser opens GitHub with a prefilled report containing the date, DocBlocks version and surface, and browser user-agent string. Review the report before submitting it. Document contents are not inserted into that report automatically.

Changes to this page

This page changes when DocBlocks’ use of the network changes. The date at the top shows the latest revision, and the page’s history is public in the DocBlocks repository.

Questions and corrections

For a privacy question or a correction to this page, open an issue in the DocBlocks repository. Do not include private document contents or credentials in a public issue.
