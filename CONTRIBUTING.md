# Contributing to DocBlocks

DocBlocks does **not** accept source code contributions from outside project
maintainers. Pull requests that change source code, tests, dependencies,
configuration, generated files, or project documentation outside `specs/` will
be closed.

## Accepted contributions: proposals only

If you would like to suggest a fix or a new capability, you may submit a
specification or prompt proposal:

1. Search the [existing issues](https://github.com/bendyline/docblocks/issues)
   and the [`specs/`](specs/) directory for related requests.
2. Add one Markdown document under `specs/` with a short, descriptive filename.
3. Describe the problem, requested outcome, proposed specification or prompt,
   acceptance examples, and relevant constraints or edge cases.
4. Open a pull request that contains only that proposal document.

Do not include an implementation or changes to any other files. A proposal is a
request for the maintainers to consider, not an agreement that it will be
accepted or implemented.

For a bug report, feature suggestion, or support request that does not need a
full proposal, please [open a GitHub issue](https://github.com/bendyline/docblocks/issues/new)
or see [SUPPORT.md](SUPPORT.md).
